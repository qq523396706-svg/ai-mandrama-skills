# Seedance 批次运营

把批量生成当作可审计的作业队列，而不是连续点击。每个输出都必须能回到批准输入、一次具体提交和一个本地文件。

## 允许启动的条件

正式批次需要：批准的剧本、设计基准、镜头计划、真实时长预演，以及覆盖费用、素材上传、人物肖像和声音使用的生成授权。只验证工具时使用不带项目身份的占位输入，并标记 `SANDBOX_RUN`。

本 Skill 接收已批准的任务文本。提示词由 `$seedance-video-prompt` 或等效编译器产生；批次运营不得为了提高成功率私自改剧情、角色、动作结果或台词。

## 当天能力卡

正式提交前记录实际入口中可观察到的：平台、显示模型、日期、任务类型、时长选项、画幅和规格、参考输入限制、音频能力、输出格式、价格或额度、并发限制、查询方式和下载方式。

不能确认的字段写 `UNKNOWN_TODAY`。网页、桌面端、API 和第三方平台即使显示相似模型名，也分别建卡。

## 作业清单

每次可计费或可重试的提交使用独立作业ID，至少记录：

```text
批次ID / 作业ID / 镜头ID
批准输入版本 / 提示词摘要哈希
平台与模式 / 计划规格
参考文件及各自职责
声音方案
单次费用 / 批次上限
最大尝试数及计数口径
验收目标 / 已批准降级方式
当前状态 / 平台回执
下载文件 / 技术结果 / 创意结果
本次相对上次改变的变量
```

每个作业必须自足，不能用“沿用上一镜”替代必要输入。

## 状态规则

只使用可核验的状态：

`DRAFTED → READY → SENT → PROCESSING → RETURNED → SAVED → FILE_CHECKED → CONTENT_REVIEWED`

最终分支为 `ACCEPTED / TRY_AGAIN / FAILED / WAITING_AUTH / CANCELLED`。平台返回结果不等于已经下载；下载成功不等于内容通过。

## 代表作业

每个新的平台入口、参考组合或声音路线先选择一条能暴露主要风险的代表作业。验证提交、身份、动作、声音、下载、文件映射和实际成本后，才能扩大批次。

代表作业通过只证明路线可用，不能替代其余文件逐个登记和检查。

## 有限重试

失败先归因：输入版本、参考职责、主体或接触过多、动作和摄影机冲突、对白负荷、入口不支持、随机伪影、平台故障或后期可修。

下一次只修改与证据有关的变量，并记录旧值、新值与理由。换模型、换模式、拆镜和新增上传都属于新的成本或授权决定。达到尝试上限后停止；付费追加、提高额度或扩大上传范围不能自动执行。

## 保存和技术检查

文件名稳定包含作业ID和尝试序号。保存平台回执、提交时间、输入版本、参考列表和请求摘要，但不得把密钥、Cookie 或私人账号信息写入记录。

下载后检查：文件存在且非零、可解码、时长合理、轨道存在、规格符合预期，并且作业ID与文件一一对应。随后把真实文件交给表演、口型和终片质检。

## 批次汇报

汇报计划、获授权、已提交、返回、已保存、技术通过、内容接受、失败、重试、总尝试、已知费用、未知费用和主要失败原因。每个数字必须能由作业清单复算。
