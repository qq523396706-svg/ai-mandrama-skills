# 项目记录与恢复

项目应能从磁盘恢复，而不是依赖某次对话。目录名称可以适配团队习惯，但必须保留下列信息关系。

## 建议布局

```text
project/
  project-register.yaml
  story/
  scripts/
  design/
  plans/
  timing/
  jobs/
  edits/
  reviews/
  media/
```

`media/` 保存项目素材和生成文件，不属于 Skill 仓库。项目登记只引用路径和权利，不把素材复制进工作流包。

## 版本标识

正式交付物使用稳定ID、版本、状态、建立时间、输入版本和批准记录。建议状态：

- `WORKING`：正在修改；
- `CANDIDATE`：等待审核或选择；
- `APPROVED`：指定版本可供下游使用；
- `STALE`：输入变化后不再有效；
- `RETIRED`：保留历史但停止使用。

新版本另存，不覆盖已批准版本。下游记录引用明确版本，不写“最新版”。

## 依赖和失效

每个交付物登记直接输入。例如镜头计划引用剧本和设计版本，视频作业引用镜头计划与预演版本，最终剪辑引用具体生成文件。

输入变化时：

1. 记录旧值、新值、原因和批准者；
2. 找出直接引用者并标记 `STALE`；
3. 继续检查由这些引用者派生的结果；
4. 只重做实际受到影响的部分；
5. 复验后建立新版本，不擦除旧证据。

## 恢复顺序

1. 读取 `project-register.yaml` 的当前工作区和批准点；
2. 找到每项批准绑定的具体文件；
3. 读取最近连续性变化和 `STALE` 项；
4. 检查正在运行或已返回但未保存的外部作业；
5. 找到最近一次审核的未解决问题；
6. 给出唯一下一步，不在恢复时顺带重写历史。

若登记指向的文件不存在、哈希变化或状态互相冲突，停止受影响活动并报告。不要根据修改日期自动决定谁是权威版本。

## 敏感记录

不得在项目登记中保存 API Key、Cookie、登录令牌、私人账号信息或无必要的个人数据。对外平台只记录不含凭据的入口、任务回执和授权状态。
