# AI 漫剧制作总控

本 Skill 负责决定“现在应完成哪一项交付物、由谁完成、凭什么进入下一步”。它不把整季生产压缩成一次提示，也不替代专项 Skill 的专业判断。

## 先定位工作区

项目使用九个工作区：

`SCOPE → STORY → SCRIPT → DESIGN → PLAN → TIMING → GENERATE → ASSEMBLE → VERIFY`

开始或恢复任务时，先读项目登记、当前权威版本、批准记录、连续性变化和未解决问题，再判断所在工作区。详细进入和退出条件见 [workflow-checkpoints.md](references/workflow-checkpoints.md)。

如果用户只要求审查或诊断，停留在对应工作区给出证据，不自动实施返修。若用户要求制作，完成当前工作区的真实验收后再推进。

## 第一次接收项目

记录：用途与受众、集数与单集范围、发布渠道、当前素材和工具、事实与虚构边界、预算、尝试上限、上传权限、真人肖像、声音、音乐、字体、品牌与第三方IP权利。

不确定信息写成 `UNKNOWN`。为低风险内部规划作出的临时假设写成 `WORKING_ASSUMPTION` 并说明影响；会改变费用、权利、发布结果或不可逆操作的未知项必须等待用户决定。

可从 [starter](assets/starter/) 复制空白登记文件。只创建项目当前需要的记录，不制造无用文档。

## 六个批准点

- `STORY_ACCEPTED`：系列规则、人物驱动力和分集承诺已确认；
- `SCRIPT_ACCEPTED`：指定单集文本可以驱动正式视觉与声音设计；
- `DESIGN_ACCEPTED`：角色、场景、道具和声音身份基准已确认；
- `TIMING_ACCEPTED`：故事板、临时声音和真实时长预演能够成立；
- `GENERATION_ALLOWED`：费用、上传、肖像和声音授权覆盖实际提交；
- `DELIVERY_ACCEPTED`：最终文件完成规定观看与权利检查。

每次批准绑定交付物版本、批准者、日期和保留问题。技术测试可以使用无项目身份的占位素材，但不能替正式项目取得批准。

## 专项路由

先确定输入与责任，再调用执行器；接口见 [executor-interfaces.md](references/executor-interfaces.md)。

- 人物在镜头内的行为变化：`$emotion-performance-director`；
- 固定角色声音和逐句配音：`$mandrama-voice-director`；
- 画内对白同步：`$mandrama-lipsync-qc`；
- Seedance 多作业运营：`$seedance-batch-ops`；
- 最终候选文件验收：`$mandrama-final-qc`。

故事开发、单集写作、独立审稿、图片生成、视频提示词和剪辑可以使用目标环境中已安装的专业 Skill。引用名称只是接口，不代表本仓库包含、安装或授权该依赖。

选择执行器时写清：输入版本、它可以改变什么、不能改变什么、应返回什么、如何验证以及失败返回哪一层。只提到 Skill 名称不算实际使用。

## 各工作区的最小职责

### SCOPE

把项目愿望转换成边界、权利和成功标准。没有明确的生成与发布权限时仍可内部规划，但不能提交外部任务。

### STORY 与 SCRIPT

先确定系列为什么能持续，再写单集。故事工作产生规则、人物选择压力和每集承诺；剧本工作产生观众可见可听的行动与台词。写作者和审稿者应分离，用户或授权负责人决定是否接受版本。

### DESIGN

分别维护人物身份、服装状态、地点结构、关键道具、声音身份和视觉语言。每个参考声明它负责的属性及不负责的属性，避免一张图同时控制所有内容。

### PLAN 与 TIMING

先安排人物位置、视线、行动和物件交接，再决定摄影如何观察。故事板负责定格信息；真实时长预演负责对白速度、动作时间和剪辑关系。静态故事板不能证明复杂运动已经可行。

### GENERATE 与 ASSEMBLE

每个可提交任务使用独立ID并绑定批准版本。正式批量生产交给 `$seedance-batch-ops`；声音身份和台词表现交给 `$mandrama-voice-director`。剪辑只使用获准素材，并保留声音、字幕、图形和导出边界。

### VERIFY

最终文件必须完整播放。所有画内对白先经过 `$mandrama-lipsync-qc`，再由 `$mandrama-final-qc` 汇总故事、连续性、表演、声音、技术和权利结论。

## 变更如何向下游传播

任何交付物都记录直接依赖。上游改变时，先标记受影响项为 `STALE`，再重新开放最小必要工作区：

- 故事规则或人物核心目标变化，会影响相关分集、剧本及其生产结果；
- 已批准台词、动作、人物或地点变化，会影响相应设计、镜头、预演和生成任务；
- 角色外观或声音身份变化，只影响引用该版本的镜头和后期；
- 单镜构图或动作变化，只重开该镜及其派生文件；
- 纯导出或局部混音修复不回写无关剧情。

变更记录方法见 [record-keeping.md](references/record-keeping.md)。不要覆盖旧版本来隐藏影响，也不要因局部修改重做整季。

## 每次交接必须回答

```text
当前工作区：
使用的输入版本：
本次交付物：
执行器与实际使用方式：
验证证据：
结论：READY / NEEDS_WORK / WAITING / NOT_CHECKED
仍属未知的事项：
已标记失效的下游：
下一项具体工作：
```

回复中的“完成”必须和磁盘文件、平台回执或真实播放证据对应。文件存在、按钮点击、任务返回成功、抽帧正常或某个局部检查通过，都不能单独证明成片交付。

## 恢复旧项目

恢复时以磁盘中最近一次明确批准的版本为准；聊天记忆只用于寻找线索。若磁盘记录互相冲突，列出冲突并暂停受影响工作区，不自动选择看起来更新或更美观的版本。

项目文件布局、版本命名和恢复顺序见 [record-keeping.md](references/record-keeping.md)。平台能力、价格和规则可能变化；进入正式生成或发布前重新核验当天的实际入口。
